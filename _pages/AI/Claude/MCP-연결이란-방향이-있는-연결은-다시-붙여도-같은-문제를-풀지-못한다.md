## 한 줄로

MCP 연결에는 **방향**이 있다. "A 가 B 를 도구로 부린다"와 "B 가 혼자 돈다"는 완전히 다른 구조이고, 전자를 복구해도 후자의 문제는 풀리지 않는다. 자동화 루틴이 크레딧 부족으로 멈췄을 때 "예전에 붙여뒀던 MCP 를 다시 붙이면 되지 않을까"를 확인해봤고, 답은 아니었다.

## MCP 연결의 방향

MCP(Model Context Protocol, 모델이 외부 도구를 호출하도록 규격화한 연결)를 붙이면 한쪽은 **두뇌**가 되고 다른 쪽은 **손**이 된다. 두뇌는 판단하고 호출하는 쪽, 손은 호출당해 실행하는 쪽이다. 이 역할은 대칭이 아니다. 손 쪽이 자기 두뇌로 혼자 일하는 경우, 그 일에는 두뇌 쪽 연결이 전혀 관여하지 않는다.

말로 보면 당연한데, 실제로 도구가 멈췄을 때는 이 구분이 잘 안 보인다. "예전에 둘이 연결돼 있었다"는 기억만 남고, 그 연결이 어느 방향이었는지는 기억에서 빠지기 때문이다.

## 실제로 겪은 것 — 402 는 어디서 나는가

브라우저 자동화 도구인 Aside 의 루틴이 크레딧 부족(402)으로 멈췄다. 과거 Claude와의 MCP 연결을 복구하면 해결되는지 확인했다. 확인 결과는 이렇다.


```text
(과거)  Claude(두뇌) ──MCP──> Aside(브라우저 조작 손)
(현재)  Claude(두뇌) ──────> ego lite(브라우저 조작 손)
        Aside(자체 두뇌 gpt-5.6-luna + 자체 손) ── 독립 자동화
```

위 그림에서 중요한 건 세 번째 줄이다. **Aside 루틴은 Claude 를 쓴 적이 없다.** 과거의 MCP 연결은 "Claude 가 Aside 를 브라우저 조작 손으로 부리는" 방향이었고, 루틴은 "Aside 가 혼자 정해진 시각에 도는" 반대 방향이다. 루틴이 도는 동안 Claude 는 호출되지 않는다.

| | 두뇌(모델) | 과금 |
|---|---|---|
| Claude Code | Claude Opus 5 | Claude 구독 |
| Aside 루틴 | gpt-5.6-luna | Aside 크레딧 ← 고갈 지점 |

과금 주체가 갈리는 지점이 곧 고갈 지점이다. 루틴은 자체 모델 `gpt-5.6-luna` 로 돌고 그 비용은 Aside 크레딧에서 나간다. Claude 구독과는 접점이 없다. 따라서 **MCP 를 다시 붙여도 402 는 해결되지 않는다.**

연결을 끊은 시점은 2026-09-08, 브라우저 작업을 `ego lite` 하나로 모으면서다. 근거는 `CLAUDE.md` 157번 줄과 `claude mcp list` 실측(등록 없음)이다. 즉 지금 Claude 쪽에는 Aside 등록이 남아 있지 않고, 그래도 루틴은 계속 돌고 있었다 — 이것 자체가 루틴이 Claude 와 무관하다는 증거다.

## 남은 후보 — 확인하지 않은 것

Aside 설정에 `customModels: []` 와 `asideModelCatalog` 항목이 있다. 커스텀 모델 등록을 지원하는 것처럼 보이지만, OpenAI 호환 엔드포인트를 받는지, `claude -p` 셔틀을 붙일 수 있는지는 확인하지 않았다. 된다면 크레딧 없이 루틴을 돌릴 수 있는 유일한 경로다.

여기까지가 확인된 범위다. 실제로 되는지는 아직 모른다.

## 정리

도구가 멈췄을 때 "예전에 이 둘이 붙어 있었다"는 기억은 진단 근거가 못 된다. 확인해야 할 것은 **그 연결에서 누가 두뇌였고 누가 손이었는지**, 그리고 **지금 멈춘 그 일에 두뇌 쪽이 관여하는지**다. 과금 주체가 어디로 갈리는지를 보면 방향이 드러난다.
