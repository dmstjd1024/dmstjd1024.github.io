## 한 줄로

Paseo 데몬의 `daemon.listen` 값이 Tailscale 주소로 바뀌었다. 그러자 같은 머신에서 `127.0.0.1:6767` 로 붙던 데스크톱 앱이 `Connecting` 에서 멈췄다. 두 주소를 쉼표로 이어 넣어 둘 다 듣게 하려 하자, 이번에는 데몬이 `getaddrinfo ENOTFOUND` 를 내며 죽었다. 설치된 데몬 0.17.4 는 공식 문서와 달리 `listen` 에 주소를 하나만 받는다. 결국 데몬은 `127.0.0.1:6767` 만 듣게 두고, 다른 기기는 relay(중계 서버를 거치는 연결)로 붙이기로 정했다.

## 데몬이 듣는 주소는 하나다

Paseo 는 각 머신에서 데몬이 돌고, 앱이 그 데몬에 붙는 구조다. 데몬이 어느 주소와 포트에서 접속을 받을지는 `daemon.listen` 값이 정한다.

우리 구성에서 이 값 하나가 두 쪽의 접속을 함께 좌우했다.

- **같은 머신의 데스크톱 앱**은 `127.0.0.1:6767`(루프백 주소, 자기 자신을 가리키는 주소)로 붙는다.
- **다른 기기**(맥미니, 아이폰)가 Tailscale 망으로 직접 붙으려면 데몬이 Tailscale IP 에서 들어야 한다.

데몬을 Tailscale IP 에서만 듣게 하면 루프백으로 오는 앱 접속은 거부된다. 문제가 난 곳은 회사 노트북에서 돌던 데몬이다.

## 아침: 앱이 Connecting 에서 멈췄다

아침에 회사 노트북의 Paseo 앱이 `Connecting` 상태에서 넘어가지 않았다. 확인해 보니 전날 21:11 에 데몬 네 대를 Tailscale 로 묶으면서([앞 글](/AI/Claude/herdr-세션-32개-중-29개만-Paseo로-넘어왔다.html)) `listen` 값을 Tailscale IP 로 바꿔 둔 상태였다. 앱은 여전히 `127.0.0.1:6767` 로 붙으려 했으므로 접속이 거부됐다.

값을 루프백으로 되돌리고 데몬을 재시작했다.

```bash
paseo daemon config set daemon.listen 127.0.0.1:6767
paseo daemon restart
```

첫 줄은 데몬이 듣는 주소를 루프백으로 고친다. 둘째 줄은 데몬을 다시 띄워 바뀐 값을 적용한다.

## 거부 원인은 하나 더 있었다: 4401

앱이 거부된 원인은 `listen` 만이 아니었다. 앱이 비밀번호 없이 붙고 있어서 `Password required(4401)` 가 함께 났다. 앱에 비밀번호를 넣어 이 문제는 풀렸다.

`Connecting` 이라는 증상 하나 뒤에 원인이 두 개 겹쳐 있었다. 하나를 고친 뒤에도 접속이 안 되면 다른 원인이 남아 있는지 따로 봐야 한다.

## 오후: 둘 다 들으려다 데몬이 죽었다

오후에 맥미니에서 돌던 에이전트 세션이 노트북 데몬의 `listen` 을 다시 Tailscale 쪽으로 바꿨다. 이번에는 루프백도 살리려고 주소 두 개를 쉼표로 이어 넣었다.

결과는 더 나빴다. 데몬이 `getaddrinfo ENOTFOUND` 를 내며 죽었다. `getaddrinfo` 는 호스트 이름을 실제 주소로 바꾸는 시스템 함수이고, 이 단계에서 주소를 찾지 못해 실패한 것이다. 데몬이 내려가면서 노트북 앱도 끊겼다. 17:46 에 회사 쪽 세션에서 값을 `127.0.0.1:6767` 로 되돌려 복구했다.

맥미니에서도 같은 시도를 했다가 데몬이 약 3분간 꺼졌다. 같은 설정을 다른 머신에서 시도해도 똑같이 실패한 것이다.

## 문서와 설치된 버전이 달랐다

공식 문서에는 `listen` 에 주소 여러 개를 쉼표로 넣을 수 있다고 되어 있다. 하지만 설치된 데몬 0.17.4 는 이 형식을 받지 못했다. 문서를 그대로 따른 설정이 데몬을 죽인 것이다.

이 일로 얻은 규칙은 하나다. **데몬 설정을 바꾸기 전에 설치된 버전과 문서가 설명하는 버전을 대조한다.** 같은 실수를 반복하지 않도록 에이전트 메모리에도 저장했다.

## 결정: listen 은 루프백 하나, 다른 기기는 relay

이 버전에서는 `listen` 에 루프백과 Tailscale 주소를 함께 지정할 수 없다. `0.0.0.0` 으로 열면 둘 다 받지만, 앞 글에서 정한 대로 Tailscale 밖에 데몬을 열지 않는다. 그래서 기기 간 연결을 `listen` 밖으로 뺐다.

- 회사 노트북 데몬은 `127.0.0.1:6767` 만 듣는다.
- 맥미니와 아이폰 같은 다른 기기는 relay 로 붙는다.
- 페어링은 노트북에서 `paseo daemon pair` 로 한다. 사용자가 18:02 에 페어링을 마쳤다.

이렇게 하면 다른 기기를 붙이려고 `listen` 을 건드릴 일이 없다. 로컬 앱이 끊길 일도 함께 사라진다.

## 곁가지: IP 대신 호스트 이름으로 붙기

맥북프로 데몬에는 IP 대신 Tailscale 호스트 이름으로 붙도록 했다. 이름으로 붙으려면 데몬의 허용 목록에 도메인을 넣어야 한다.

```json
"hostnames": [".<tailnet>.ts.net"]
```

이 값을 넣고 `paseo reload` 로 다시 읽게 했고, 적용됐다는 회신을 받았다. 이후에는 `<호스트명>.<tailnet>.ts.net:6767` 로 접속한다.

## 남은 것

4대 데몬이 모두 같은 비밀번호를 쓴다. 4401 은 비밀번호를 넣어 풀었지만, 이 비밀번호 공유 문제는 보안 미해결 항목으로 남아 있다.
