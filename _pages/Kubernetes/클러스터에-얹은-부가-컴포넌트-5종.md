## 한 줄로

**클러스터를 만든 뒤, 스크립트가 부가 컴포넌트 6개를 이어서 깐다.** 그런데 **하나도 안 깔려도
클러스터는 "정상" 으로 기록된다.**

[앞 글](/Kubernetes/회사마다-클러스터-하나씩-띄운다.html)에서 4단계로 넘긴 부분이 여기다.

## 무엇을 왜 얹었나

| 컴포넌트 | 역할 | 왜 필요한가 |
|---|---|---|
| **Ingress** (nginx) | 외부 트래픽 진입 | 포트가 회사당 10개뿐이라 경로로 나눠야 한다 |
| **Istio** | 서비스 메시 게이트웨이 | Fabric 오더러를 클러스터 밖에 노출 |
| **Prometheus** | 지표 수집 | 파드·컨테이너 자원 사용량 |
| **Grafana** | 지표 시각화 | Prometheus 를 사람이 보는 화면으로 |
| **쿠버 대시보드** | 클러스터 GUI | `kubectl` 없이 상태 확인 |

여기에 이미지 사전 로드까지 합쳐 6단계다.

## 포트가 모자라서 Ingress 를 쓴다

회사 하나가 받는 포트는 **10개**다. 그런데 노출할 게 그보다 많다.

그래서 관측 도구 3종(대시보드·Grafana·Prometheus)은 **포트를 따로 쓰지 않고** Ingress 의
경로로 들어간다.

```
{Ingress포트}/grafana      → grafana-svc:80
{Ingress포트}/prometheus   → prometheus-svc:9090
{Ingress포트}/kube-dashboard/
```

포트 3개를 1개로 줄인 것이다. 대신 **경로 재작성**이 필요하다.

```yaml
annotations:
  nginx.ingress.kubernetes.io/rewrite-target: /$2
spec:
  rules:
  - http:
      paths:
      - path: /grafana(/|$)(.*)
        pathType: ImplementationSpecific
```

`/grafana/foo` 로 들어온 요청에서 **`/grafana` 를 떼고** `/foo` 로 넘긴다. 정규식의 두 번째
괄호가 `$2` 다. 이걸 안 하면 Grafana 는 `/grafana/foo` 라는 경로를 자기 기준으로 해석하려다
404 를 낸다.

`proxy-read-timeout: 3600` 도 붙어 있다. Grafana 의 실시간 갱신처럼 **연결을 오래 붙잡는
요청**이 기본 타임아웃(60초)에 끊기기 때문이다.

## Grafana 대시보드를 파일로 심는다

대시보드를 손으로 만들면 클러스터를 다시 깔 때마다 다시 만들어야 한다. 그래서 **JSON 파일로
두고 자동 등록**한다. 지금 2개가 들어 있다 — 파드 개요, 컨테이너 자원.

방식이 재밌다. Grafana 를 건드리지 않고 **ConfigMap 에 라벨만 붙인다.**

```bash
kubectl create configmap "grafana-dashboard-${name}" \
  --from-file="${name}.json=${file}" -n monitoring --dry-run=client -o yaml | \
kubectl label --local -f - grafana_dashboard="1" -o yaml | \
kubectl apply -f -
```

핵심은 `grafana_dashboard=1` 이다. Grafana 옆에 붙은 **사이드카 컨테이너**(보조 컨테이너)가
이 라벨이 달린 ConfigMap 을 감시하다가, 발견하면 대시보드로 읽어들인다.

즉 **Grafana 에 API 를 호출하지 않는다.** 쿠버네티스 리소스를 만들면 Grafana 가 알아서
따라오는 구조다. 선언적이라 재설치에도 그대로 재현된다.

다만 마지막에 이런 줄이 있다.

```bash
kubectl rollout restart deployment -n monitoring -l app.kubernetes.io/name=grafana
```

사이드카가 감지한다면서 **재시작을 시킨다.** 감지 주기를 기다리지 않고 즉시 반영하려는 것으로
보이는데, 이미 대시보드를 보고 있던 사용자는 이 순간 연결이 끊긴다.

## 폐쇄망이라 이미지 출처를 전부 갈아끼운다

이 시스템은 인터넷이 끊긴 망에서 돈다. Docker Hub 에서 이미지를 받을 수 없다.

그래서 서버에 **로컬 레지스트리**(`localhost:5001`)를 띄우고, 설치할 때마다 이미지 출처를
그쪽으로 바꿔 지정한다. Istio 설치가 대표적이다.

```bash
ISTIO_IMAGE="localhost:${LOCAL_REGISTRY_PORT}/istio"
istioctl operator init --hub "${ISTIO_IMAGE}" --tag="${ISTIO_TAG}"
```

Helm 으로 까는 것들은 `--set` 으로 이미지 경로를 하나하나 덮어쓴다. 모니터링 하나 까는 데
이미지 지정만 8개가 들어간다.

**레지스트리는 회사별이 아니라 서버 전체가 공유한다.** 클러스터는 회사마다 따로지만, 이미지
저장소는 하나다. 같은 이미지를 회사 수만큼 중복 저장할 이유가 없기 때문이다.

## 여기서 걸린 것 — 다 실패해도 "정상"이다

부가 컴포넌트 설치는 전부 이렇게 감싸여 있다.

```bash
bash "$SCRIPT_DIR/04-install-monitoring.sh" ... || {
  echo "⚠️ ... non-critical, continuing..."
}
```

**실패해도 넘어간다.** 6개 전부 그렇다.

의도 자체는 이해된다. Grafana 가 안 깔렸다고 클러스터를 통째로 버릴 이유는 없다. 블록체인
네트워크는 그것 없이도 돈다.

문제는 **그 사실이 아무 데도 안 남는다**는 점이다. 스크립트는 정상 종료하고, 자바는 이렇게 한다.

```java
agency.setClusterStatus(ClusterStatus.ACTIVE);
```

Ingress 도 모니터링도 대시보드도 하나도 없는 클러스터가 **`ACTIVE`** 로 기록된다.
어떤 컴포넌트가 실제로 올라갔는지 기록하는 필드도 없다.

사용자는 Grafana 링크를 눌러보고 나서야 안 깔렸다는 걸 알게 된다. 그때 남는 단서는 몇 분 전
셸 로그의 `⚠️` 한 줄뿐이다.

**부분 성공을 성공으로 기록하면, 실패는 사라지는 게 아니라 나중으로 미뤄진다.**

## 대시보드는 파일이 없으면 아예 안 깔린다

한 가지 다른 케이스가 있다. 쿠버 대시보드 스크립트는 매니페스트를 **파일로 읽는다.**

```bash
DASHBOARD_YAML="${KIND_CLUSTER_DIR}/configs/kubernetes-dashboard-v2.7.0.yaml"
if [ ! -f "${DASHBOARD_YAML}" ]; then
  echo "❌ Dashboard YAML not found: ${DASHBOARD_YAML}"
  exit 1
fi
```

폐쇄망이라 `kubectl apply -f https://...` 를 못 쓰니 파일을 미리 갖다둬야 한다.

이건 앞의 것들과 달리 **`exit 1` 로 명확히 실패한다.** 원인도 메시지에 찍힌다. 좋은 처리다.

다만 이 실패조차 **호출부에서 `|| { … continuing }` 로 삼켜진다.** 스크립트는 제 할 일을
제대로 했는데 바깥에서 무시하는 셈이다.

## 정리

- 포트가 회사당 10개뿐이라 **관측 도구 3종을 Ingress 경로로 몰았다** — `rewrite-target` 필수
- Grafana 대시보드는 **ConfigMap + 사이드카 라벨**(`grafana_dashboard=1`)로 심는다.
  API 호출이 아니라 선언적이라 재설치에 강하다
- 폐쇄망이라 **모든 이미지 출처를 로컬 레지스트리로 갈아끼운다.** 레지스트리는 서버 공용
- ⚠️ 6개가 **전부 실패해도 클러스터는 `ACTIVE`** 다. 무엇이 깔렸는지 기록도 없다
- 대시보드만 `exit 1` 로 정직하게 실패하는데, **그마저 호출부가 삼킨다**
