## 한 줄로

**부가 컴포넌트 중 유일하게 "없으면 못 깐다" 고 명확히 실패하는 스크립트다.**

그런데 그 정직한 실패조차 **호출부에서 무시된다.** 이 글은 그 대비에 대한 이야기다.

## 폐쇄망이라 매니페스트를 파일로 갖고 있다

쿠버네티스 대시보드는 보통 이렇게 깐다.

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/dashboard/...
```

**여기서는 못 한다.** 인터넷이 없다.

그래서 YAML 을 서버에 미리 갖다 두고 파일 경로로 적용한다. 그리고 없으면 이렇게 한다.

```bash
DASHBOARD_YAML="${KIND_CLUSTER_DIR}/configs/kubernetes-dashboard-v2.7.0.yaml"

if [ ! -f "${DASHBOARD_YAML}" ]; then
  echo "❌ Dashboard YAML not found: ${DASHBOARD_YAML}"
  echo "Please ensure the file exists for offline installation."
  exit 1
fi
```

**`exit 1` 이다.** 무엇이 없는지, 어디에 있어야 하는지까지 찍어준다.

이게 왜 특별하냐면, 같은 계열의 다른 스크립트들은 그렇지 않기 때문이다.
[Grafana 편](/Kubernetes/grafana-대시보드를-파일로-심는다.html)에서 본 대시보드 폴더 확인은
없으면 **아무 말 없이 넘어간다.**

| 스크립트 | 파일이 없을 때 |
|---|---|
| 쿠버 대시보드 | **`exit 1` + 경로 안내** |
| Prometheus 차트 | `exit 1` |
| Grafana 대시보드 폴더 | **조용히 건너뜀** |
| Istio 게이트웨이 설정 | 경고만 |

## 이미지 경로를 sed 로 바꾼다

파일로 갖고 있으니 문제가 하나 생긴다. 그 YAML 안의 이미지 주소는 **Docker Hub 를 가리킨다.**
폐쇄망에서는 못 받는다.

그래서 적용하기 전에 문자열을 치환한다.

```
kubernetesui/dashboard:        →  localhost:5001/kubernetesui/dashboard:
kubernetesui/metrics-scraper:  →  localhost:5001/kubernetesui/metrics-scraper:
```

Helm 은 `--set` 으로 값을 바꾸면 되지만, **생 YAML 은 그런 수단이 없다.** 텍스트를 직접
고치는 수밖에 없다.

이 방식의 약점은 **YAML 구조를 모른다**는 점이다. 새 버전에서 이미지 표기가 조금만 달라지면
치환이 빗나가고, 그러면 파드가 이미지를 못 받아 멈춘다. 그때 스크립트는 성공으로 끝난다.

## HTTPS 백엔드라 Ingress 설정이 다르다

대시보드는 자기 자신이 **HTTPS 로 뜬다.** 그래서 Ingress 설정이 Grafana·Prometheus 와 다르다.

```yaml
annotations:
  nginx.ingress.kubernetes.io/backend-protocol: "HTTPS"
  nginx.ingress.kubernetes.io/rewrite-target: /$2
  nginx.ingress.kubernetes.io/ssl-redirect: "false"
  nginx.ingress.kubernetes.io/proxy-ssl-verify: "false"
```

네 줄이 각각 다른 문제를 푼다.

| 설정 | 없으면 |
|---|---|
| `backend-protocol: HTTPS` | nginx 가 HTTP 로 말을 걸어 연결이 깨진다 |
| `rewrite-target` | 대시보드가 `/kube-dashboard/...` 를 못 알아본다 |
| `ssl-redirect: false` | HTTP 접근이 HTTPS 로 튕겨 무한 리다이렉트가 난다 |
| `proxy-ssl-verify: false` | 자체 서명 인증서를 nginx 가 거부한다 |

마지막 두 개가 특히 실전에서 나온 값으로 보인다. 대시보드는 **자기가 만든 인증서**(자체 서명)를
쓰는데, 이걸 검증하려 들면 통과할 방법이 없다. 그래서 검증을 끈다.

경로 재작성 자체는 [Ingress 편](/Kubernetes/ingress로-포트-3개를-1개로-줄였다.html)과 같은
원리다.

## cluster-admin 토큰을 만든다

대시보드로 뭔가 보려면 권한이 필요하다. 스크립트는 계정을 하나 만들고 최고 권한을 준다.

```yaml
kind: ClusterRoleBinding
metadata:
  name: admin-user
roleRef:
  kind: ClusterRole
  name: cluster-admin      # ← 클러스터 전체 관리자
```

그리고 이 계정의 **토큰을 Secret 으로 발급**해둔다.

`cluster-admin` 은 그 클러스터에서 할 수 있는 모든 것을 할 수 있는 권한이다. 대시보드로
파드를 지우거나 시크릿을 읽는 것도 포함된다.

이 시스템에서는 **클러스터가 회사 단위로 격리**돼 있어 피해 범위가 그 회사 클러스터로 한정된다.
[클러스터 격리 글](/Kubernetes/회사마다-클러스터-하나씩-띄운다.html)에서 본 구조가 여기서
안전판 역할을 한다.

다만 토큰이 만료되지 않는 Secret 형태로 남는다는 점은 기억해둘 만하다. 읽기 전용으로 충분한
용도라면 `view` 클러스터롤로 낮출 여지가 있다.

## 여기서 걸린 것 — 정직한 실패가 삼켜진다

이 글의 요지다. 스크립트는 제 할 일을 제대로 한다. 파일이 없으면 `exit 1` 로 끝내고 이유를
알려준다.

그런데 **호출부가 이렇게 돼 있다.**

```bash
bash "$SCRIPT_DIR/06-install-kubernetes-dashboard.sh" ... || {
  echo "⚠️ ... non-critical, continuing..."
}
```

`exit 1` 이 `|| { … }` 에 걸려 **경고 한 줄로 강등된다.** 그리고 클러스터는 `ACTIVE` 로
기록된다.

즉 이런 상황이 된다.

```
스크립트:  "❌ Dashboard YAML not found: ...  (exit 1)"
호출부:    "⚠️ non-critical, continuing..."
DB:        clusterStatus = ACTIVE
사용자:    대시보드 링크를 눌러보고 나서야 안다
```

**정보가 세 단계를 거치며 사라진다.** 스크립트는 정확한 원인을 알고 있었고, 그걸 표준적인
방법(종료 코드)으로 알렸는데, 바깥에서 그 신호를 버린다.

이건 스크립트의 잘못이 아니다. **실패를 잘 알리는 것과, 그 신호를 받아 처리하는 것은 다른
문제**라는 걸 보여주는 사례다.

## 정리

- 폐쇄망이라 대시보드 매니페스트를 **파일로 갖고 있다.** URL 로 못 받는다
- 없으면 **`exit 1` + 경로 안내** — 부가 컴포넌트 중 가장 정직한 실패 처리다
- 생 YAML 이라 이미지 경로를 **`sed` 로 치환**한다. 표기가 바뀌면 조용히 빗나갈 수 있다
- 자기가 HTTPS 로 떠서 Ingress 설정이 다르다 — **`backend-protocol` · 리다이렉트 차단 ·
  인증서 검증 해제** 네 줄이 각각 다른 문제를 푼다
- 접근용으로 **`cluster-admin` 토큰**을 만든다. 클러스터가 회사 단위로 격리돼 피해 범위는 한정적
- ⚠️ **`exit 1` 이 호출부의 `|| { … }` 에 걸려 경고로 강등된다.** 잘 알린 실패가 버려진다
