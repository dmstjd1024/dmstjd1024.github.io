# 블로그 글쓰기

이 블로그의 글은 **경험담**과 **정리·비교** 두 계열뿐이다. 먼저 어느 쪽인지 정하고,
그 계열의 골격을 따른다. 섞으면 둘 다 아닌 글이 된다.

## 순서

1. **계열을 정한다** — 아래 판별표
2. **같은 카테고리 최근 글 1~2편을 실제로 연다** — 규칙만 읽고 쓰지 않는다 (아래 "참조 규칙")
3. **사실을 확보한다** — `references/sourcing.md`
4. **골격에 맞춰 쓴다** — `references/structure.md`
5. **문장 규칙을 적용한다** — `references/voice.md`
6. **프론트매터를 붙인다** — `references/frontmatter.md`
7. **도식이 필요하면 그린다** — `blog-diagram` 스킬을 읽는다
8. **자체 검사한다** — 아래 체크리스트
9. **빌드로 확인한다** — `bundle exec jekyll build`

## 계열 판별

| 신호 | 계열 | 마지막 섹션 |
|---|---|---|
| 내가 겪은 일, 고친 일, 터진 일이 있다 | 경험담 | `## 남는 교훈` |
| 개념·도구를 설명하거나 둘을 비교한다 | 정리·비교 | `## 정리` |

마지막 섹션 제목이 두 계열의 구분 신호다. 140편 중 **57편이 `## 남는 교훈`,
35편이 `## 정리`** 로 끝난다 (2026-09-18 실측). 나머지는 2023년 옛 글이라 이 관행 이전이다.

⚠️ 이 숫자는 글이 늘면 낡는다. **인용하지 말고 아래를 직접 돌린다.**

```bash
grep -rl '^## 남는 교훈' _pages --include='*.md' | wc -l   # 57
grep -rl '^## 정리'      _pages --include='*.md' | wc -l   # 35
```

## 참조 규칙 — 규칙 파일만 읽고 쓰지 않는다

글을 쓰기 전에 **같은 카테고리의 최근 글 1~2편을 직접 연다.** 이 파일들의 규칙은
추상화된 것이라 결을 다 담지 못한다. 원문이 그 틈을 메운다.

```bash
CAT=Database   # 쓰려는 카테고리
for f in _pages/$CAT/*.md; do
  [ "$(basename "$f")" = "index.md" ] && continue
  echo "$(git log -1 --format='%ad' --date=short -- "$f")  $f"
done | sort -rn | head -2
```

⚠️ `ls -t` 를 쓰지 않는다 — 이 머신의 `ls` 는 eza 별칭이고, 파일 수정 시각은
글 작성 순서와 무관하다 (체크아웃하면 전부 같아진다).
`git log --diff-filter=A -- '_pages/<카테고리>/'` 도 쓰지 않는다 — 하위 폴더의
2023년 글이 먼저 나온다 (실측 2026-09-18).

카테고리에 글이 없거나 한 편뿐이면 `_pages/Database/` 또는 `_pages/Spring/` 의
최근 경험담을 대신 본다.

## 자체 검사

글을 다 쓴 뒤 아래를 직접 확인한다. 하나라도 걸리면 고치고 나서 넘긴다.

- [ ] **측정하지 않은 숫자가 있는가** — 커밋·로그·실측에 근거가 없는 수치는 지우고
      원인을 특정하는 문장으로 바꾼다. 이게 다른 모든 규칙을 이긴다.
- [ ] **규칙 파일의 수치를 그대로 옮겼는가** — 이 스킬의 숫자는 낡는다.
      글에 쓸 값이면 레포에서 다시 센다 (`references/sourcing.md`).
- [ ] **"N편" 이 파일 수가 맞는가** — `grep -c` / `rg -c` 는 줄 수다. 파일 수는 `-l | wc -l`.
- [ ] **감성 표현이 남았는가** — "열정", "성장", "전진" 류. 마무리 구호도 삭제.
- [ ] **H2 가 명사구로 굳어 있는가** — "인덱스 최적화" 가 아니라 "그런데 안 빨라졌다".
- [ ] **제목이 주제만 적은 명사구인가** — "~구축기", "~정리" 로 끝나면 다시 쓴다.
      결과나 반전이 제목에 있어야 한다 (`references/structure.md` 의 "제목").
- [ ] **코드블록에 해설이 없는가** — 앞이나 뒤에 이게 무슨 의미인지 한 줄.
- [ ] **마지막 섹션 제목이 계열과 맞는가** — 경험담이면 `## 남는 교훈`.
- [ ] **남겨둔 것을 밝혔는가** — 경험담이면 이번에 안 고친 것과 그 이유.
- [ ] **도식이 `.diagram` 으로 감싸였는가** — `{% include %}` 만 쓰면 검게 나온다.

## 빌드 확인

Liquid 문법이 본문을 먹는 사고가 실제로 있었다 (커밋 `c116582`).
`{{` 나 `{%` 가 본문 코드블록에 들어가면 `{% raw %}` 로 감싼다.

```bash
bundle exec jekyll build
```

## 피드백을 규칙으로 남긴다

글을 넘긴 뒤 지적을 받으면, 그게 **이 글 한 편의 문제가 아니라 반복될 성질**일 때만
해당 `references/` 파일에 한 줄 추가한다. 추가할 때는 **근거가 된 글 이름을 같이 적는다.**
한 번짜리 취향은 남기지 않는다 — 규칙 파일이 지저분해지면 아무도 안 읽는다.
