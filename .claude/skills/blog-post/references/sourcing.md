# 사실을 어디서 가져오나

글의 재료는 세 갈래다. **어느 갈래든 숫자는 근거가 있는 것만 쓴다.**

## 0. 먼저 — 이게 누구의 경험인가

다른 무엇보다 먼저 묻는다. **1인칭으로 쓸 수 있는 것은 사용자가 겪은 일뿐이다.**

에이전트나 도구가 **자기 작업 중에 낸 오류는 사용자의 경험이 아니다.**
세션 대화에 사실이 다 있어도, 그 판단을 한 주체가 사용자가 아니면
"나는 ~했다", "세어보니 아니었다" 로 쓰지 않는다.

| 주체 | 1인칭으로 쓸 수 있나 |
|---|---|
| 사용자가 코드를 고치다 겪은 일 | O |
| 사용자가 내린 설계 판단 | O |
| **에이전트가 규칙 파일을 쓰다 낸 실수** | **X** |
| **에이전트가 자기 명령을 잘못 짜서 틀린 통계** | **X** |

구분이 어려우면 이렇게 묻는다 — **"면접관이 '어떻게 하셨어요?' 하고 물으면
사용자가 답할 수 있나."** 답이 에이전트의 사고 과정이면 사용자 글이 아니다.

⚠️ 실제로 이걸 어긴 초안이 나온 적이 있다. 에이전트가 이 스킬을 만들면서
낸 오류 4개를 "내가 확인하지 않은 주장을 네 개 썼다" 로 1인칭 경험담을 썼다.
사실은 전부 맞았지만 **주체가 사용자가 아니어서 폐기했다.**

**애매하면 글로 쓰지 말고 보고에 적는다.** 사용자가 판단할 몫이다.

## 1. 세션 대화

메인 세션에서 방금 한 작업을 글로 남기는 경우. 가장 흔하다.

- 무엇을 고쳤는지, 왜 그렇게 했는지가 이미 대화에 있다
- **틀린 시도가 대화에 남아 있으면 그게 글의 핵심 재료다** — 지우지 말고 `## 1차 시도` 로 쓴다
- 대화에 없는 수치를 채워 넣지 않는다

⚠️ **대화에 있다고 다 사용자의 경험은 아니다.** 같은 세션에 에이전트가
자기 작업 중 낸 실수도 섞여 있다. 0번을 먼저 통과시킨다.

## 2. 레포의 커밋과 코드

측정치의 1차 출처다. 커밋 메시지에 남은 값만 인용한다.

```bash
git log --oneline -20
git log -1 --format='%B' <sha>          # 커밋 본문에서 측정치 찾기
git show <sha> --stat                   # 변경 규모
git log -S '<검색어>' --oneline         # 그 코드가 언제 들어왔나
```

`gin-trigram` 글의 "13일" 과 `캐시를-고쳤는데` 글의 "산정 10k 48s → 0.085s" 가
이렇게 나온 값이다. **커밋 날짜 차이는 직접 잰 값이므로 써도 된다.**

변경 규모를 쓸 때도 실제 값으로:

```bash
git show <sha> --shortstat              # "130개소 남짓", "373줄 변경"의 근거
```

## 3. 조사 (WebSearch / WebFetch / 공식 문서)

정리·비교 계열에서 쓴다.

- 공식 문서를 1차 출처로 본다. 블로그 글을 재인용하지 않는다
- 버전을 명시한다 — 동작이 버전에 따라 다르다
- **직접 돌려본 것과 문서에서 읽은 것을 구분해서 쓴다**

```
(O) 문서상 기본값은 0이다
(O) 실측 2026-08-22 — 노드 16개를 flowchart LR 로 그리면 2543px 한 줄로 펴진다
(X) 약 2배 빠르다                        ← 출처 없음
```

## 숫자가 없을 때

이게 제일 자주 걸리는 상황이다. **숫자를 지어내는 대신 원인을 특정한다.**

| 쓰지 않는다 | 대신 쓴다 |
|---|---|
| 조회가 40% 빨라졌다 | 항목마다 쿼리가 따로 나가던 구조였다 |
| 응답 시간이 크게 줄었다 | 그룹 수만큼 더해지던 대기시간 → 가장 느린 요청 1건 시간 |
| 상당한 성능 개선 | 행 100건을 정렬하려고 전 회사 데이터를 100번 훑고 있었다 |

오른쪽 문장들은 **들여다본 사람만 쓸 수 있는 표현**이다. 숫자보다 강하다.

## 셸로 통계를 낼 때 — 단위를 먼저 정한다

글에 "N편" 이라고 쓰려면 **파일 수**를 세야 한다. 그런데 셸 도구의 기본 단위는
대개 **줄 수**다. 이 둘을 섞으면 숫자가 몇 배로 어긋난다.

같은 패턴으로 실측한 값 (2026-09-21):

| 명령 | 값 | 단위 |
|---|---|---|
| `rg -l '—' _pages -g'*.md' \| wc -l` | 102 | **파일 수** ← 글에 쓸 값 |
| `rg -c '—' _pages -g'*.md' \| wc -l` | 102 | 파일 수 (우연히 같음) |
| `rg -c '—' ... \| awk -F: '{s+=$NF} END{print s}'` | 1406 | 줄 수 합계 |

`-c` 는 **파일당 매치 줄 수**를 `파일:개수` 로 출력한다. 그 출력을 `wc -l` 하면
파일 수가 나와 맞아떨어지지만, 값을 합하면 1406 — **자릿수가 다르다**.
**"N편" 을 셀 때는 `-l | wc -l` 하나만 쓴다.**

⚠️ 위 값은 글이 한 편만 늘어도 바뀐다. 실제로 이 표의 첫 값은
103/1416 이었다가 글 한 편이 빠지면서 102/1406 이 됐다.
**논지는 "두 값이 자릿수만큼 다르다"이지 특정 숫자가 아니다.**
글에 인용할 거면 그 자리에서 다시 센다.

### 프론트매터 통계는 grep 으로 세지 않는다

`grep '  - '` 는 프론트매터의 태그와 본문의 들여쓴 불릿을 구분하지 못한다.
실측: `AI` 80편이 106으로, `Spring` 18편이 34로 나왔다.

고약한 점은 **일부만 틀린다**는 것이다. `Claude Code` 는 78/78로 정확했다 —
본문에 그 문자열이 안 나오기 때문이다. 결과를 훑어봐서는 이상한 줄 모른다.

프론트매터 통계는 `references/frontmatter.md` 의 파이썬 파서를 쓴다.

### 같은 함정의 세 얼굴

이 블로그 작업에서 실제로 나온 오독 셋이다. 전부 **"이 명령이 무엇을 반환하는가"**
를 잘못 읽은 것이고, 결과가 그럴듯해서 검산 없이 넘어갔다.

| 명령 | 반환하는 것 | 착각한 것 | 결과 |
|---|---|---|---|
| `rg -c '패턴'` | 파일당 매치 **줄 수** | 파일 수 | 제목 대시 "0개" → 실제 50 |
| `grep -rhF '  - '` | `  - ` 로 시작하는 **모든 줄** | 프론트매터 태그 | `AI` 80 → 106 |
| `git ls-tree -r <브랜치>` | 브랜치의 **전체** 파일 | 그 커밋이 추가한 파일 | 커밋에 없는 파일을 있다고 판단 |

세 번째는 `git show --stat <커밋>` 이 정답이다. 커밋이 **바꾼** 것만 보여준다.

**출력 형태를 한 번 눈으로 보고 나서 센다.** `| wc -l` 이나 `| head -3` 을
붙이기 전에 날것을 본다.

### 검산으로 판단을 뒤집기 전에, 그 검산을 한 번 더 본다

앞의 셋은 "명령이 무엇을 반환하는가"를 오독한 것이다. 이건 종류가 다르다 —
**검산 자체를 틀리는 바람에 맞는 문장을 틀렸다고 판단하고 지운** 경우다.

실제 사례. 규칙 파일에 `(비율도 13.7→13.8)` 이라고 적었다가,
검산했더니 13.75와 13.78이 나와서 "둘 다 13.8로 반올림되니 틀린 서술"이라며 지웠다.

```
1416/103 = 13.7476   → 소수 1자리로는 13.7
1406/102 = 13.7843   → 소수 1자리로는 13.8
```

**원래 문장이 맞았다.** 소수 2자리(13.75/13.78)로 재놓고 소수 1자리 서술을
판정한 것이 실수다. 자릿수를 섞으면 맞는 것이 틀려 보인다.

- 검산 결과가 **기존 판단을 뒤집을 때** 특히 위험하다. 뒤집는 쪽이 새 정보처럼
  느껴져 검산 자체는 재확인하지 않게 된다
- **원문과 같은 정밀도**로 비교한다. 소수 1자리 서술은 소수 1자리로 판정한다
- 지우기 전에 "이 문장이 맞는 경우가 있나"를 한 번 묻는다

(이 건은 결과적으로 지운 게 맞았다. 다만 **이유가 달랐다** — "틀린 서술이라서"가
아니라 "경고문 안의 절대값도 낡아서"다. 옳은 행동을 틀린 근거로 하면
다음번에 같은 근거로 옳지 않은 행동을 한다.)

### 규칙 파일에 적힌 수치도 그대로 믿지 않는다

이 파일들의 숫자는 **적힌 시점의 값**이다. 글이 쌓이면 낡는다.
글에 인용할 값이면 옆에 붙은 명령을 그 자리에서 다시 돌린다.

⚠️ 실제로 이 스킬의 규칙 파일에 틀린 실측치가 박힌 적이 있고,
에이전트가 그걸 "측정된 값" 으로 보고 글에 인용했다.
**규칙 파일은 1차 출처가 아니다.** 1차 출처는 레포다.

## 민감 정보

공개 레포다. 글에 넣기 전에 확인한다.

- 사용자명·머신 식별자·내부 호스트명 → 자리표시자로 치환 (커밋 `dcdabb0` 에서 실제로 했던 일)
- 사내 도메인·티켓 번호·고객사명 → 일반화하거나 뺀다
- 토큰·키 → 절대 넣지 않는다. 예시가 필요하면 명백한 더미로

도메인을 일반화한 예 — `toctou` 글의 "B2B 산업용 관리 시스템",
`gin-trigram` 글의 "장비 목록 화면". 무엇을 하는 시스템인지는 남기고
어느 회사인지는 지운다.
