# 문장 규칙

두 층이다. **상위는 `CLAUDE.md` 의 취업 원칙**이고, 하위는 기존 글에서 뽑은 문체다.
충돌하면 언제나 `CLAUDE.md` 가 이긴다 — 특히 "측정하지 않은 것은 쓰지 않는다".

## 상위 규칙 (CLAUDE.md 에서)

### 측정하지 않은 숫자를 쓰지 않는다

가장 강한 규칙이다. 근거 없는 수치 하나가 **정확한 다른 문장까지 의심받게** 만든다.

- 커밋 메시지·로그·실측에 남은 값만 쓴다
- 반올림된 퍼센트("45% 향상")보다 어중간한 실측치가 강하다
- 숫자가 없으면 **원인을 특정하는 문장**으로 대체한다

```
(X) 조회 성능이 약 40% 개선됐다
(O) 항목마다 쿼리가 따로 나가던 구조였다
(O) 산정 10k 48s → 0.085s          ← 커밋에 남아 있는 값
```

### 감성 표현을 쓰지 않는다

"열정", "성장", "전진", "노력했다" 류. 정보가 0이고 오히려 마이너스다.
팩트를 쓰고 독자가 스스로 느끼게 한다. 마무리 구호도 삭제한다.

### 과장하지 않는다

자동화로 줄어든 것이 *사람이 붙어 있는 시간*이면 그렇게 쓴다.
벽시계 시간이 그대로면 "N분 → M분" 은 거짓이다.

## 문체 (기존 글에서)

### 불릿이 기본 단위다

이 블로그는 문단보다 불릿을 많이 쓴다. 특히 사실 나열 구간에서 그렇다.
`대시(—)` 나 `콜론(:)` 으로 라벨과 내용을 가른다.

```markdown
- 발견 — 배출계수 상세조회가 탭을 나갔다 올 때마다 매핑된 그룹 수(N건)만큼 재호출
- 원인 — API 슬라이스 기본값이 `keepUnusedDataFor: 0` (캐시 없음)
- 조치 — 상세조회 엔드포인트만 `keepUnusedDataFor: 300`으로 오버라이드
```

근거 — `toctou`, `gin-trigram` 은 거의 전부 불릿이고,
`캐시를-고쳤는데-안-빨라졌다` 는 불릿과 문단을 섞는다.

**단, 판단·해석은 문단으로 쓴다.** 불릿은 사실을 나르고, 문단은 의미를 준다.
전부 불릿이면 "그래서 뭐"가 안 남는다.

### 굵게는 논지 한 문장에만

섹션마다 굵은 문장이 하나쯤 있고, 그게 그 섹션의 결론이다. 여러 개 굵게 하면 강조가 사라진다.

```markdown
**증상은 "목록이 느리다"였는데 나는 목록 쿼리를 한 번도 보지 않았다.**
**가장 빠른 부분일치 검색은 부분일치를 하지 않는 것이다.**
**인덱스를 만든 것과 인덱스가 쓰이는 것은 별개의 사건이다.**
```

### 코드블록에는 해설이 붙는다

앞이나 뒤에 이게 무슨 의미인지 한 줄. 코드만 던지지 않는다.
코드 안 주석으로 의도를 적는 것도 이 블로그의 습관이다.

```java
// 원격 디렉토리는 셸 mkdir -p 로 원자적으로 보장한다.
// SFTP 의 stat/mkdir 루프는 동시 업로드 시 TOCTOU race 가 발생하므로 사용 금지.
```

수정 전후를 보여줄 때는 두 블록으로 나누고 각각에 `-- 수정 전` / `-- 수정 후` 주석을 단다.

### 처음 쓰는 용어는 괄호로 한 번 푼다

`TOCTOU(Time-of-check to time-of-use)`, `trigram(3글자 단위)`,
`비-sargable`. 풀고 나면 그 뒤로는 그냥 쓴다.

### 1인칭을 쓰되 감정은 안 쓴다

"나는 전자를 골랐고, 그게 틀렸다" 는 쓴다. "아찔했다" 는 안 쓴다.
틀린 판단을 숨기지 않는 게 이 블로그의 성격이다.

### 표는 설명을 대체할 때만

설명을 다 쓰고 표를 덧붙이면 짧아지지 않는다.
선택지 비교, 시간순 요약처럼 **표가 문단보다 짧을 때만** 쓴다.

### 문장을 짧게 끊는다

한 문장에 한 가지만 담는다. 접속사로 이어붙이지 않는다.

```
(X) 캐시를 적용하고 병렬화도 했지만 화면은 여전히 느렸는데, 그 이유는 고친 곳이 병목이 아니었기 때문이다.
(O) 두 조치 모두 그 자체로는 옳다. 그런데 화면은 여전히 느렸다.
```

## 하지 않는 것

- 도입부에 "이번 글에서는 ~에 대해 알아보겠습니다" 류의 예고 — 바로 본론으로 들어간다
- 섹션 끝마다 요약 반복 — 마지막 섹션에서 한 번만
- 이모지 — 본문에 쓰지 않는다
- "~인 것 같다", "~일 수도 있다" 의 남발 — 확실하지 않으면 왜 확실하지 않은지를 쓴다
